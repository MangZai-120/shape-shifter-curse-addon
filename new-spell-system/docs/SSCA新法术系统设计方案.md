## 目录与系统边界

**本方案是与现有法术体系隔离的新体系，统一收在[`new-spell-system`](../README.md)中。** 现有法术书、卷轴、法力、法阵、熟练度、冷却与施法流程保持原有行为，不被本方案自动替换。

新体系分别管理施法入口、法术定义、崩解度状态、恢复、熟练度、施法会话、冷却、网络与HUD。新法术的具体入口物品、按键和构建方式待定，不默认把当前书内或单独卷轴施法接入崩解度。

下文提到“像当前蓝条一样逐步结算、等待后恢复”，指玩法节奏和算法参考；实际状态与流程在新体系内独立实现。旧代码链接仅用于对照，不表示要直接修改或接管旧管理器。

## 一、核心规则：一条向上累积的崩解度条

**法术使崩解度条向上增长。当前形态的身体稳定度决定这条上的安全阈值：阈值以内没有崩解引发的失败、偏移或负面效果；超出后，每个检测点根据当时真实崩解度、本次法术的实际消耗与当前形态的抽卡修正，重新计算概率。**

身体稳定度与崩解度在同一个计算空间中，不分别维护一条稳定度资源和一条崩解度资源。所谓“先消耗稳定度”，就是先占用安全阈值以内的空间；安全空间用尽后，继续累积才进入危险区。

```text
崩解度条：从0开始向上增长

0 ─────── 当前形态的安全范围 ─────── S ── 超出0–20 ── 超出20–60 ── 超出60以上 →
                                      ↑
                               身体稳定度阈值
```

核心变量统一为：

| 符号 | 含义 | 是否独立资源 |
| --- | --- | --- |
| C | 崩解度条当前的累计值 | 是，唯一需要累计与恢复的条值 |
| S | 当前形态的身体稳定度，即安全阈值 | 否，是形态参数 |
| E＝max(0, C−S) | 当前超出安全范围的真实点数，是实时风险计算的输入 | 否，由C和S计算 |
| R＝max(0, S−C) | 剩余安全空间，可用于界面提示 | 否，由C和S计算 |
| Q | 本次法术经过熟练度等修正后的实际总消耗 | 否，是本次施法报价 |
| FormRoll | 当前形态对崩解抽卡的修正配置 | 否，是独立于安全阈值的形态参数 |

因此，不应同时执行“扣一个稳定度数值”和“加另一个崩解度数值”，造成重复支付。安全空间减少与危险负担增加，是同一条向上增长在不同区段的表现。

### 1.1 安全区的保证

当本次检测时C不超过S，崩解机制引发的失败率和偏移率均为0，不施加崩解负面效果。法术按原本瞄准和锁定位置执行。

这里的精准性100%表示没有系统新增的随机偏移，不改变原法术的射程、碰撞、遮挡、目标合法性和控制状态限制。

### 1.2 明确排除的后果

施法、崩解和反噬不会使玩家变成幻形生物。玩家即使因反噬死亡，也不会生成野生幻形生物。

## 二、各形态的身体稳定度与抽卡修正

每个形态分别配置身体稳定度S与崩解抽卡修正FormRoll。S决定安全线在哪里，FormRoll决定超过安全线后抽卡有何差异；两者分别配置，不能只靠安全阈值差异代替抽卡加成。

| 形态 | 讨论中的参考S | 崩解抽卡修正 | 数值状态 |
| --- | ---: | --- | --- |
| 人类 | 100 | 独立配置 | S为原始参考值，抽卡修正待定 |
| 美西螈 | 80 | 独立配置 | S为本轮参考值，抽卡修正待定 |
| 使魔 | 200 | 独立配置 | S为讨论参考值，抽卡修正待定 |
| SP悦灵 | 50–80 | 独立配置 | S的具体值与抽卡修正均待定 |
| 其他形态 | 分别配置 | 分别配置 | 完整数值表待补充 |

以上举例不代表所有子形态、升级形态与SP形态共用同一参数。需要按实际形态ID建立完整映射。

### 2.1 抽卡加成是独立的形态差异

即使两个形态在检测时具有相同E、使用相同实际消耗Q的法术，它们也可以因FormRoll不同而有不同抽卡结果分布。使魔的S＝200只说明安全空间较大，不能据此直接认定其超额后的失败率、偏移率或严重异常概率具体降低多少。

FormRoll采用加值、倍率还是独立曲线，以及对失败、偏移、其他异常分别怎样修正，尚待定数。偏转角度和状态强度是否也有形态修正需要单独说明，不能默认所有结果统一乘同一个系数。

任何形态修正都遵守安全区保证：C≤S时，崩解引起的失败、偏移和负面效果均为0。

### 2.2 换形态直接重置

**切换形态时，当前崩解度条重置为0，并使用新形态的身体稳定度S与抽卡修正FormRoll。** 不保留旧条值，不按比例转换，也不保存一份可切回取用的旧形态负担。

例如，美西螈S＝80、C＝95时，超出15点；切换为使魔后，C＝0、S＝200，重新处于安全状态。

熟练度不属于这条资源，不因重置崩解度条而自动清空。已经获得的负面状态是否随换形态解除，以及施法准备中切换形态如何结束当前会话，需另行确定。

## 三、每个法术分别计算消耗

### 3.1 独立基础消耗

不同法术有各自的基础消耗，同一法术的不同施放档位也可以不同。不能给所有法术套用一个统一消耗。

```text
本次实际总消耗 Q
＝该法术、该档位的基础消耗
 × 适用的符文、法阵、形态等代价修正
 × 身体适应倍率
 × 已确认启用的其他代价修正
```

具体乘区需要随旧系统迁移逐项确定。原始讨论保留了连续施法加重负担的方向，但窗口、倍率和与恢复等待的关系尚未定数，本稿不沿用旧草案的固定1.50倍率。

Q增加到C上。C未超过S时，表现为剩余安全空间减少；超过S的部分形成E。熟练度降低Q后，这两种负担都会减少。

### 3.2 一次施法跨越安全线

例如S＝80、C＝70，某法术实际消耗Q＝25，完整施法后：

```text
C＝70＋25＝95
剩余安全空间R＝0
超额崩解E＝95−80＝15
```

这次施法前10点消耗占用剩余安全空间，后15点进入危险区，不另外再收取一份25点的崩解费用。

### 3.3 实际消耗参与实时风险计算

风险计算读取检测时真实C及其超额E，再结合实际Q与当前形态的FormRoll。Q使用熟练度、符文、法阵等修正后的值，不使用未减免的基础值，也不使用本次2 tick分段刚增加的少量值代替整次Q。

在同一形态、相同当前E下，实际总消耗越大的法术，失败风险越高，偏移风险及偏转幅度也越高。法术档位通过实际消耗等已确认属性参与计算，不额外按“几级法术”直接套用一个固定抽卡档位。

内部应保留足够精度，避免逐段取整漏掉尾差，或让熟练后的低消耗法术变成免费施法。

## 四、渐进支付与每10 tick检测

### 4.1 渐进支付

新体系采用与当前蓝条类似的渐进支付方式，独立按进度增加C。起手锁定整次实际消耗Q，再按施法进度结算；正常完成时补齐尾差。现有法术继续原来的扣蓝方式。

支付频率与抽卡频率是不同概念。新体系参考现有支付节奏，不把“每10 tick检测”误写成每10 tick才支付一次，也不与旧体系共用支付账本。

- 起手前被冷却、目标条件、状态封锁等拒绝，不支付代价，不开始崩解抽卡。
- 开始后中断、取消或失稳失败，已经增加的C保留。
- 未运行的后续进度不提前支付，不因失败补收剩余整次费用。
- 瞬发法术在0 tick完成本次支付与检测，再决定是否产生效果。

同一tick中建议先结算该时点应付的增量，再使用更新后的C计算风险；这是待确认的执行顺序。非瞬发的0 tick应付多少，沿用其实际支付进度，不为了检测额外预收整次Q。

### 4.2 已确认的检测时间

**从0 tick开始，每隔10 tick检查一次失败和偏移等异常。**

| 施法准备时长 | 检测时点 |
| --- | --- |
| 瞬发 | 0 |
| 20 tick | 0、10、20 |
| 40 tick | 0、10、20、30、40 |
| 35 tick | 0、10、20、30；35 tick正常结清并释放，不额外新增一个10 tick检测点 |

40 tick法术的最后一次检测发生在效果成立前，检测通过后才产生效果。不能在末次检测前先造成伤害、治疗或召唤，再把它判作未释放成功。

每个检测点读取当时真实C、计算E，读取当前形态的FormRoll，并结合实际Q重新计算失败与异常概率。不能把起手时算出的概率一直沿用，也不能等跨过20或60的分界后才更新。

若抽到完全失败，立即中断会话，停止后续检查和后续支付，进入本次法术的完整CD；不能同tick重复处理失败。

### 4.3 效果产生后不再受本次抽卡影响

一旦法术效果已经成立，本次每10 tick的失败和异常检查结束：

- 已发出的投射物不再因新的抽卡消失或改变方向。
- 已召唤的生物不因后续抽卡减少或被撤销。
- 已经发生的治疗、伤害或传送不重新判定。
- 持续效果产生后，不继续抽取崩解失败来打断它，也不反复改写其效果量。

旧草案中“持续效果期间每秒再次抽失败、每秒追加超载伤害”的规则移除。原法术本身的持续支付、自然结束和外部打断仍按其原有生命周期处理，不能借此自动新增一份持续费用。

等待手动释放、长按蓄力等特殊模式的具体检测时长，应按“效果成立前的施法阶段”逐一标定，不能把持续实体存活时间全部当作施法准备时间。

## 五、实时抽卡与整次累计失败率

### 5.1 超额区间描述风险，不决定固定概率

这里的0–20、21–60、大于60，都是E，不是C的绝对值，也不是整条百分比。

| 条件 | 风险描述 | 实时计算要求 |
| --- | --- | --- |
| C≤S，即E＝0 | 安全 | 不发生崩解引起的失败、偏移或负面效果 |
| 0<E≤20 | 轻度崩解 | 使用当前真实E、实际Q与形态修正，不给整个区间统一概率 |
| 20<E≤60 | 中度崩解 | 仍随当前真实数值变化，不能只在进入中度时跳一次档 |
| E>60 | 重度崩解 | C和E仍可继续增加，实时风险及严重负面效果继续加重，可以致死 |

因内部可能存在小数，文案中的“21–60”在计算上指大于20至60，不留下20与21之间的空白区间。

**这些区间用于说明风险和设计状态，不是抽卡概率档位。** 同为轻度崩解，E＝2、E＝10、E＝19也要按各自真实值计算，不能全部套用“轻度失败率”。概率应随实时数值变化，具体函数或逐值曲线另行定数。

E>60并不直接锁死为100%失败。失败概率可以随负担继续增长到100%，具体到达位置由实时计算规则与形态修正共同确定；到100%后概率不再增长，但崩解数值和惩罚强度仍可以继续增长。

### 5.2 每个检测点的计算输入

以下是输入关系，尚未指定具体系数或曲线：

```text
当前超额 E(t)＝max(0, C(t)−S(当前形态))

本次检测失败率 p失败(t)
＝失败函数(E(t), 实际Q, FormRoll(当前形态))

本次检测偏移率 p偏移(t)
＝偏移函数(E(t), 实际Q, FormRoll(当前形态))
```

其他异常的抽取同样读取当前负担与适用的形态修正。偏转角度和异常幅度随真实负担计算，其具体形态修正范围另行配置。

同一施法会话中，C增加后，后一次检测按新的E重新计算；药水等使C降低后，后续风险也随之重算。已经完成的检测不重抽，已经累计的偏移不因概率下降而自动复原。

相同形态、相同E与Q应使用相同规则，不因本次法术还有几个检测点而人为稀释或抬高单次概率。施法时长影响会经历多少次检测，整次风险由这些实时检测自然累积。

### 5.3 10%是平衡参考，不是预先分配的风险额度

此前确认的“典型中位情境整次约10%失败”保留为平衡校准参考。实际抽卡始终按当前状态计算，不能为了凑出10%，在起手时把风险分配给未来各个检测点。

对于一条给定的状态变化路径，各次条件失败率为p₀、p₁……时，整次累计失败率为：

```text
整次累计失败率 P＝1−(1−p₀)×(1−p₁)×……×(1−pₙ)
```

例如各次实时计算得到0%、0%、1%、3%、6%，则整次累计失败率约为9.73%。这些数值只用于演示累计关系，不是已确定的概率配置。若每次都是10%，5次累计约40.95%，也不能把它称为整次10%。

旧稿“按整次目标概率倒推每次概率”“按预计强度分配风险预算”的接入建议移除。调整平衡时，应修改实时函数、形态修正或实际代价，再观察典型施法的累计结果。

HUD优先显示含当前形态修正的本次检测风险。若另行显示整次预计风险，需要说明预测前提，并随实际负担变化更新，不能用这个预估值决定真实抽卡。

## 六、偏移、锁错与效果异常

### 6.1 每10 tick更新，结果允许累积

偏移与失败在同一检测节奏中计算。没有抽到完全失败时，仍可能出现位置偏移、目标变更或效果减弱。

**位置偏移可叠加。** 第一次偏移后，后续偏移以已经偏移的内部施法方向或目标位置继续计算，不每次都还原到原始目标。每次偏移概率按当时真实负担与形态修正重新计算，偏转角度按适用的实时规则计算；不按轻、中、重三个标签直接给出固定概率和角度。

偏移修改本次法术的内部瞄准结果，不强制转动玩家镜头、调乱键位或把鼠标准星拖走。界面应通过目标标记、落点预览或偏移范围提示异常。

### 6.2 按法术类型定义异常

| 法术类型 | 已确认允许的异常 |
| --- | --- |
| 指向性、投射物或准星选点 | 指向位置偏离原准星锁定点，偏转可以累积 |
| 锁定实体 | 直接释放失败、锁定其他目标，或施放位置偏离正常锁定目标 |
| 召唤 | 召唤失败，或实际召唤数量减少 |
| 治疗 | 治疗失败、治疗量减少，或治疗变成伤害 |
| 传送 | 传到前方其他位置，实际距离减少，落点不保证安全 |

这不再只是投射物的扩散角度。每个法术要声明适用的异常类型，不能让治疗、召唤等因为没有投射弹道而免除异常，也不能让不相关的异常被无差别套用。

传送异常允许不安全结果，不能自动吸附回原来的安全落点。它仍需满足引擎层面的有效维度、有效坐标等要求；这些检查不等于保证玩家不会摔落、窒息或进入其他危险位置。

锁定到其他目标、治疗反转为伤害时，仍需走该效果正常的目标及伤害权限校验，不以“崩解异常”为理由跳过既有保护规则。

### 6.3 完全失败与带异常完成

- 完全失败：法术效果不成立，立即中断，保留已支付负担，进入完整CD并结算反噬。
- 带异常完成：法术产生了偏移、减量、锁错或反转后的效果，使用最终累计异常结果，不自动恢复原值。

数量与效果衰减如何叠加、同次施法能否重复反转治疗、锁错目标的候选范围、各类异常是否互斥，均需要在每种法术的适配表里说明。

效果成立时锁定最终结果。此后不再因本次崩解检查修改飞行中的弹体、存活中的召唤物或已经生效的结果。

## 七、反噬、负面状态与完整CD

### 7.1 完全失败的固定结算

失稳完全失败时：

1. 立即中断当前施法，不执行尚未成立的原效果。
2. 保留已经支付、已经累积的C，不返还，不补收未运行部分。
3. 进入本次法术完整CD，并写入新体系内部同法术的共享冷却，不写入旧体系冷却表。
4. 沿用反噬扣血与负面状态方向，依据危险程度处理。
5. 不增加本次法术熟练度。

完整CD按本次实际使用档位及适用冷却修正后的正常完整CD计算，不改成普通中断的缩短CD。同一失败只结算一次，不因多枚弹体或多目标重复扣血、重复建CD。

若新体系以后采用有次数的施法载体，次数如何随失败扣除需要单独明确。当前旧卷轴不自动接入，也不因新体系失败而扣次数。

### 7.2 保留已有两个负面状态

| 状态 | 沿用的效果 | 尚待明确 |
| --- | --- | --- |
| 魔力失调 | 持续5秒，无法施法，移动速度−15%；原文为失败后45%概率附加 | 基于实时E的适用条件，以及形态是否修正该条件概率 |
| 散解崩除 | 持续15秒，无法施法，移动速度−35%，失明 | 实时触发概率、形态修正范围、覆盖与刷新规则 |

45%是已经失败后附加状态的概率，不是整次法术失败率。反噬与状态都不能在安全区由崩解机制触发。

### 7.3 重度崩解可以致死

E>60后允许更严重的负面状态和反噬，继续施法和进一步累积可能导致死亡，不强制保留最后1点生命值。

可进一步设计持续身体损伤等严重状态，但具体名称、持续时间、伤害频率、是否可净化以及减伤方式尚未确认。旧稿按比例封顶的伤害公式与“停手后绝不继续受伤”的约束不再作为定案：严重状态是否在停手后继续伤害，应在该状态中明示。

普通前置拒绝、主动取消和外部打断不自动等于崩解失败，不额外抽取一次反噬。其他系统原有的完全定身、净化和中断结算继续保持各自语义。

## 八、恢复与月尘药水

### 8.1 延迟后自动降低同一条值

新体系恢复方式与当前蓝条的节奏类似：施法使C增加，停止增加后等待一定时间，再自动降低C，最低降到0。恢复没有第二份“稳定度回满”流程，也不读写旧法力恢复状态。

例如S＝80、C＝95时，先降到80便回到安全范围；继续下降会逐渐腾出更多安全空间。

等待时长、每秒降低量、施法阶段暂停恢复和再次支付刷新等待的参数在新体系中独立配置，可以参考现有蓝条的体验，但不直接绑定旧配置。是否加入静止加速、冲刺减速、受伤重置等待等额外条件尚未确认，不作为当前固定规则。

已经存在持续效果，不自动等于玩家仍在准备施法。是否暂停恢复按真实施法会话与原有支付规则判断，不能仅因场上还存在召唤物或法术实体而永久暂停。

### 8.2 月尘药水

保留月尘合成缓解药水的方向，作用是降低C，帮助返回安全范围或恢复安全空间。它不会同时操作两套稳定度与崩解度资源。

| 形式 | 原定角色 |
| --- | --- |
| 试管装 | 使用较快，降低量较少 |
| 瓶装 | 使用较慢，降低量较多 |
| 喷溅型 | 复用投掷与范围生效机制，便于紧急使用或队友支援 |

配方、降低量、使用时间和共享冷却均待定。药水降低C不代表自动清除已经存在的反噬状态，是否具有净化能力需单独说明。

## 九、熟练度与法术成长

### 9.1 按单个法术记录

新体系熟练度按单个新法术记录，不是全系共享，也不是一本书练满后所有法术一起减负担。建议按玩家与新法术ID独立保存，变更施法载体不重复练习；不读取、消耗或迁移旧体系的书经验与法术熟练度。

只有成功施法增加熟练度。起手拒绝、取消、中断和完全失败均不增加。产生了异常结果的完成，例如治疗反转、召唤减量，是否计作熟练度意义上的成功，还需明确。

高等级魔法更难提升熟练度，低等级魔法更容易提升。应通过每次成功获得的进度或所需总进度配置体现；各等级对应数值待定，不能继续使用旧稿“所有等级相同成功次数达到固定折扣”的表。

### 9.2 降低的是同一条的实际代价

熟练度提高后，Q下降：安全区内占用的空间减少，危险区内增加的超额负担也减少。安全阈值S本身仍由形态决定，不随某个法术熟练度一起变动。

**一般情况下，练熟后最低保留正常消耗的35%–50%。** 这是最终剩余消耗，不是只减免35%–50%。具体下限按单个法术配置。

例如某法术正常消耗40，练熟后若保留35%，实际消耗为14；若保留50%，实际消耗为20。

因为失败和异常使用实际Q判断，熟练度也会通过降低Q改善危险区表现。熟练度不自动增加伤害、治疗或召唤数量；若需要额外威力成长，应独立列出。

不同施放档位如何贡献同一个法术的进度，是否限制用低档反复施放快速练熟高档，需在成长表中明确，不能在实现时自行增加惩罚。

## 十、HUD与玩家反馈

界面只显示一条崩解度条，在条上标出当前形态安全阈值，并区分安全段与超额危险段。

| 信息 | 显示要求 |
| --- | --- |
| 当前条值与阈值 | 当前C、当前形态S，安全线位置清楚 |
| 当前阶段 | 安全，或当前超额点数及描述性阶段；阶段名称不代替实时概率 |
| 本次法术 | 实际Q、已经支付量、尚未支付量、完成后预计位置 |
| 风险 | 当前单次检测概率及适用形态修正；若提供整次预估，另行标注，不能混用 |
| 异常 | 位置偏移范围、当前锁定对象、累计效果减量等适用信息 |
| 恢复与状态 | 等待恢复、正在恢复、反噬状态与禁施法剩余时间 |

显示示例，仅说明信息关系：

```text
美西螈 · 身体稳定度80
崩解度条95 · 超出安全线15点 · 轻度崩解
本次消耗25，已支付10，剩余15
累计瞄准偏移：按本次施法的实际结果显示
```

不强制把条长固定到S而隐藏超额数值，也不在E＝60时把真实值截断。具体条宽、超额展开和高值压缩方式由HUD设计另定。

现有法术蓝条、原生形态技能及其他系统的资源仍按各自规则显示和使用。新体系有独立崩解度HUD；两种体系都可用时的显示切换需要另行设计，不通过移除旧HUD来实现隔离。

## 十一、独立实现与现有体系的关系

### 11.1 两种“稳定度”分别标明用途

| 名称 | 语义 |
| --- | --- |
| 身体稳定度S | 当前形态在崩解度条上的安全阈值 |
| 符文构建稳定度 | 研究、装配时用于判断方案合法性的预算 |

符文构建稳定度不直接成为第二条战斗资源。稳定符文也不自动获得清除C、提高身体S或保证施法不失败的能力，除非另外设计确认。

既有《SSCA符文强化与稳定度完整计划书》仍适用于旧体系，不因新体系的随机失败规则而修改。该旧计划是本地参考资料，位于`docs/plans/formation-research/SSCA符文强化与稳定度完整计划书.md`，未纳入本分支的版本管理。新体系若使用符文构建，需要单独定义或通过明确适配接入；不能把旧体系合法方案自动变成采用崩解规则的新法术。

### 11.2 新体系独立管理运行流程

新体系需要自己的施法管理器与会话，统一管理渐进支付、0/10/20等检测点、累计异常和一次性失败结算。新体系内部共用一份会话，新旧体系之间不共用有状态的会话实例。

可以参考旧 [SpellManaPayment](../../src/main/java/net/jackcooper/shapeShifterCurseAddon/spell/SpellManaPayment.java) 的渐进计算，以及 [SpellCastManager](../../src/main/java/net/jackcooper/shapeShifterCurseAddon/spell/SpellCastManager.java)、[SpellChannelManager](../../src/main/java/net/jackcooper/shapeShifterCurseAddon/spell/SpellChannelManager.java) 的生命周期拆分，但不在这些旧入口中替换mana或插入新抽卡。旧 [BarKeys](../../src/main/java/net/jackcooper/shapeShifterCurseAddon/resource/BarKeys.java) 与原生ManaComponent也保持不变。

新体系源码、数据、资源与测试收在`new-spell-system/src/`。用户已授权进入游戏实现阶段，试验田现在通过独立source set与Fabric入口加载新体系；旧管理器仍不接管。

起手应保存法术ID、实际档位、Q、准备时长、完整CD、熟练度修正与起手上下文；施法期间保留支付进度、检测序号与累计异常。每个检测点重新读取当时真实C及当前形态的S、FormRoll，不冻结起手概率，也不用整次结束时的预计值提前惩罚仍在安全区的玩家。

若最终规则允许施法中换形态后继续会话，后续检测必须读取新形态配置；若换形态中断会话，则结束后不再抽卡。不能在尚未决定中断方式时，隐含保留旧形态的抽卡加成。

各法术需要实现最终目标、方向、召唤数量、治疗量及正负性质、传送位置等异常结果的实际消费者，不能只保存数据而不改变行为。

### 11.3 数据与兼容边界

旧法力消耗、法阵耗蓝、形态折扣、法术书容量、增能、回蓝、返蓝与精通奖励保留在旧体系。新体系分别定义自己的消耗、修正、恢复和成长参数，不默认继承旧奖励，也不重写旧物品字段与玩家进度。

现有单独卷轴继续现有规则。若以后需要新载体、旧卷轴转换、Perk适配或新旧体系共享某些冷却，必须逐项设计，不能在本轮隐含启用。新体系仍应遵守现有目标保护、完全定身及净化等通用玩法约束，具体通过独立适配执行。

## 十二、算例、验收与待定数值

### 12.1 规则算例

**安全施法：** 美西螈S＝80、C＝20，法术Q＝25。即使完整支付后C＝45，也始终在安全区，所有崩解检测均不失败、不偏移。

**逐渐跨线：** S＝80、C＝70、Q＝25。随着支付，C先到80，此前安全；继续增加后进入轻度崩解，最后C＝95、E＝15。风险只从跨线后的实际检测点开始计算。

**失败保留部分代价：** Q＝25的40 tick法术，在20 tick已支付12.5点时抽到失败，则保留12.5点，剩余12.5点不再支付，效果不成立，进入完整CD并结算反噬。

**实时检测：** S＝80、起手C＝70、Q＝25的40 tick施法，在0、10、20、30、40 tick按均匀进度结算时，C依次为70、76.25、82.5、88.75、95，E依次为0、0、2.5、8.75、15。前两次安全，后三次各用自己的真实E、同一个实际Q和当前形态修正重新抽卡；后三次都属于轻度，不代表概率相同。

**形态抽卡差异：** 对比两个形态在相同E、相同Q下的单次检测，分别使用各自FormRoll得到概率。不能只给它们不同S，再把超额后的抽卡规则全部视为相同。具体谁更有利及差多少，等待配置确认。

**累计结果：** 若一次施法的实时条件概率依次为0%、0%、1%、3%、6%，累计约9.73%。这描述实时检测的累计结果，不是先定9.73%再向各次分摊。

**换形态重置：** 美西螈C＝95、S＝80，切换使魔后C＝0、S＝200，不保留原先15点超额或95点累计值。

**熟练度减负：** 正常Q＝40的法术，熟练后保留35%–50%，Q降至14–20；占用的安全空间与进入危险区后增加的负担一起减少。

### 12.3 历史待定项（已由V2和实现记录具体化）

1. 各形态S、独立抽卡修正FormRoll、各法术与档位的基础消耗、连续施法修正。
2. 以实时E、实际Q与FormRoll为输入的单次失败及异常概率函数，偏转角度与异常强度曲线，以及形态修正的具体覆盖范围。
3. 重度崩解达到100%失败的条件、严重状态内容、反噬伤害与减免方式。
4. 各类法术异常的抽取、累积、互斥和目标范围，异常完成是否增加熟练度。
5. 同tick支付与抽卡的先后、手动等待释放的检测时长，以及新体系若使用次数载体时的失败扣次规则。
6. 换形态时当前施法与已有负面状态如何处理；重登、跨维度、死亡后的持久化规则。
7. 自动恢复参数、药水配方与参数、各法术熟练度曲线及低档训练高档的规则。
8. 新体系自己的入口载体、命名空间、独立构建方式、法阵与Perk适配范围；现有卷轴及旧体系奖励保持原有行为。
