# 新法术系统稳定性测试与修复

日期：2026-10-27。分支：`neomagic`。修复版本：`8.0.0-neomagic.2`。

## 本轮结论

本轮复现并修复了起手时序、非法笔记请求的部分写入、大研究数据的网络包超限、畸形NBT解析开销，以及快速关闭界面的会话回收问题。修复后进行了模型压力、实际服务端、多玩家状态、磁盘反复存取、服务端重启与原生客户端回归。

以下多人测试使用同一实际ServerWorld中的8个模拟玩家及本地测试连接，不是真人通过网络登录。GameTest加速推进服务端tick，因此“一小时游戏时间”不能表述为“一小时真人在线运行”。

## 已复现的问题和修复

| 问题 | 修复前证据／影响 | 修复 |
| --- | --- | --- |
| 起手tick重复推进 | 20 tick法术会提前结束；补充检查了瞬发CD及恢复等待的起算边界 | 保存会话起始tick，起手当tick不再推进准备；新CD及最近支付不会在同tick额外倒计时 |
| 非法笔记请求部分写入 | 引用超长被拒绝前，假说／结论已被修改 | 先校验整份请求，再一次性写入；失败请求不改变原文 |
| 大研究快照超过网络上限 | 12,000个合法术式身份的进度产生1,317,695字节JSON，触发`Payload may not be larger than 1048576 bytes` | 压缩后59,079字节，逐字节往返一致；解压有预算，发送前检查包大小；使用新版状态通道 |
| 畸形NBT解析长停顿 | 本机Windows环境中，通用NBT错误路径构造Minecraft CrashReport，进入WMI硬件查询；线程证据保留在本地构建目录 | 只解析本协议允许的平面字段，限制总长、字段、类型、UTF长度及UUID数组，避开通用错误报告路径 |
| 保存后立即关闭留下后台会话 | 关闭请求被同tick限速丢弃 | 先验证会话身份，再优先处理关闭，不让清理请求被普通操作限速挡住 |

另外增加了失败结算幂等保护、存档及客户端快照结构校验、过多引用的防死循环保护。客户端先完整解析新快照再更新界面，损坏压缩数据不会部分覆盖当前数据。新记录同时保存引擎版本，旧记录不重写。

## 压力与持续运行结果

| 层次 | 实际范围 | 结果 |
| --- | --- | --- |
| 纯模型 | 200,000次随机施法，从3,043份合法配置样本中抽取；6,180,924个模拟tick，穿插498,710次缓解负担事件 | 20,242,056项不变量检查通过；安全区、有限数值、渐进支付、终止后不重复支付／抽卡均成立 |
| 大数据和异常请求 | 12,000个合法术式身份；32名玩家；64,000次历史插入；32轮实际磁盘保存／读取；20,000条畸形请求 | 21,072项检查通过；历史上限和引用保留成立，玩家数据不串，损坏数据被拒绝 |
| 畸形请求耗时 | 20,000次解析，包含NBT形状、长度和尾随数据边界 | 修复后约0.041秒完成；这是本机单轮测量，不是通用性能保证 |
| 实际ServerWorld持续测试 | 8个模拟玩家，72,320个服务端tick；1,895次施法尝试；实际运行297.35秒 | 578,907项检查通过，无测试失败；主体施法阶段72,000 tick相当于一小时游戏时间 |
| 生命周期 | 同一持续测试中有1次断线重连、1次实际死亡重生、1次形态组件切换及2次异步数据包重载 | C、CD、适应和记录保持预期隔离；变形中断当前准备；重生清C且保留适应 |
| 效果清理 | 停止发起新施法后等待320 tick，自然排空 | 施法会话、投射物、召唤物及储存结构均为0；并非先调用强制清理后再测量 |
| 峰值容器 | 持续测试中观察到最多5个会话、6枚弹体、13个召唤物 | 未出现持续增长的效果容器残留；不等同于证明整个Minecraft没有任何内存泄漏 |
| 实际重启 | 停止测试服务器，再用同一个测试世界启动新进程 | 8名玩家共16项研究／状态恢复检查通过 |
| 原生客户端 | 实际Minecraft客户端接收压缩快照，拒绝损坏快照，再渲染四页与320×240界面 | 正常数据到达真实接收函数，坏数据未改变当前数据和会话；界面边界检查通过 |

重连与重生使用服务端正常处理路径。形态切换测试直接改动形态组件以检查新体系响应，不替代完整变形动画、全部形态Perk及第三方兼容验收。

```powershell

.\new-spell-system\tools\build-neomagic.ps1 -Isolated -Tasks @('-PneoResume=true','neoMagicStabilityTest')
```

普通功能、客户端界面与完整构建也已回归。原始运行日志和测试世界留在`build/neomagic/`，本轮不读取或修改用户现有游戏存档。

## 使用和验收边界

客户端与服务端需要一起更新到`8.0.0-neomagic.2`，因为研究状态消息已升级。原有试验田持久化格式保持兼容。

这些证据支持“本轮所覆盖的压力与生命周期场景未再复现上述问题”。真人多客户端网络延迟／丢包、第三方领地保护矩阵和连续数小时至数天的实际在线运行，仍未验收。
