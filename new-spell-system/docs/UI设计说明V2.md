# 新法术研究UI设计 V2

日期：2026-10-27。对应[完整系统设计](SSCA新法术系统完整设计V2.md)。

[打开交互原型](../ui/研究界面原型.html)。这是界面与规则演示，尚未接入Minecraft。

## 一、整体布局

采用四页共用外框的研究工作台。顶部保留研究主题、蓝图名称与四个页签；页内围绕当前任务组织信息，不把所有功能堆到同一画面。

主视觉为暗蓝石板、细金线术式盘和淡色纸签。危险区以朱红／琥珀色及文字共同表达。界面不使用持续强闪烁、强制摇晃或占据视线的特效。

## 二、观测页

任务：选择研究材料，知道已观察到什么、还有什么需要解释。

- 左侧是样本与现象目录，明确“已有样本”“候选解释”“已验证规律”。
- 中间显示样本结构片段、可测量现象和关联记录。
- 右侧显示可执行动作：设为基准、查看记录、带入构式页。
- 一条现象可以关联多份实验，不能因为点开样本就自动生成完整正确答案。

## 三、构式页

任务：改造并保存一份可以被检验的术式。

| 区域 | 内容与交互 |
| --- | --- |
| 左栏元件库 | 作用核、载形和控制符文，悬停解释含义与代价；不适配项说明原因 |
| 中央术式盘 | 来源、作用核、载形及控制通路；点击节点查看用途与当前参数 |
| 右栏参数 | 作用规模、准备时间、组织方式；高级参数按需展开 |
| 身体承载摘要 | 当前形态、C、安全阈值S、超额E、报价Q与当前单次风险 |
| 底栏 | 保存基准、复制变式、验证结构／预览、制作蓝图 |

空控制位表示直通。结构错误标记具体节点与连接，不用“失败”两个字让玩家盲试。

当前单次风险按现在的C计算；完整支付后的预计C单独显示。不能把未来预计风险伪装为本次实时检测风险。

## 四、实验页

任务：比较条件与结果，判断解释是否得到支持。

1. 选择基准与变式记录。
2. 先显示条件差异，包括形态、起始C、作用量、准备时间、组织和目标。
3. 结果分别显示到达作用量、真实伤害／治疗、命中数量与异常；没有真实测量的字段留空。
4. 时间线逐点显示支付、当前超额、失败与偏移概率、实际抽卡结果。
5. 可把两条记录引用到一条假说或结论，不自动把随机结果判成规律。

偏移分布图同时保留样本数。没有足够数据时使用“样本较少”等明确说明，不伪造精准统计。

## 五、笔记页

分开呈现三种内容：

- 观察：系统生成的事实与记录引用。
- 假说：玩家手写、可修改的解释。
- 结论：注明适用条件并引用对照记录的归纳。

分享蓝图或笔记时保留结构和证据，不复制身体适应、材料或他人进度。旧版本记录保留版本标签。

## 六、原型的可操作范围

原型可以切换四页，调整作用量、准备时间、初始负担与形态，选择普通／分流／汇合，保存基准、运行规则预览并查看记录、比较和编辑笔记。

规则预览使用设计默认的报价、实时抽卡与作用预算。它不是游戏伤害测量，不包含世界实体、碰撞、网络、实际物品或Minecraft渲染；原型记录明确称作“演算记录”。

原型的本地保存只服务于设计评审，不能导入后直接成为真实服务器的研究进度。

## 七、游戏落地规格

- 游戏内文字使用字体渲染，所有文案进入中英文语言资源。
- 原型中的矢量术式盘是构图说明；游戏美术可据此绘制PNG，保留节点坐标与点击区域一致。
- 窄屏或高GUI缩放时，侧栏改为切换页，主要操作不被裁掉。
- 同时区分“无法构建”“起手拒绝”“主动中断”“崩解失败”“带异常完成”。
- 保存、制作与施法由服务器复核，客户端预览不写真实C、经验、材料或结果。
- 页内文案优先解释玩家能作出的选择，不显示Java类名、NBT键或原始网络字段。
